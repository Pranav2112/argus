# ARGUS

> Chubb sees where an event happened. ARGUS shows where its consequences travel.

Hackathon prototype for contingent business interruption: which insured businesses depend on suppliers hit by an event, and which of those links were already observed failing in a past event (dependency memory: Kumamoto 2016 → Kyushu 2026).

All portfolio accounts are **SYNTHETIC**.

## Setup

```bash
npm install
cp .env.local.example .env.local   # set OPENAI_API_KEY + OPENAI_MODEL (or ANTHROPIC_API_KEY)
```

## Before the demo

1. Paste article text into `data/articles/A1.txt` … `A5.txt` and `T1.txt` … `T5.txt` (mapping and URLs in `data/articles.json`; check `published_at` dates there).
2. Run:

```bash
npm run prepdemo   # usgs → extract → explain (all results cached in data/)
npm test           # blast-radius unit tests (incl. Kyushu 2026 tier baseline)
npm run replay     # Taiwan 2024 tiers after each source, with the causing claim
npm run dev        # http://localhost:3000
```

After this, the demo runs without network except for map tiles and the live USGS feed (which falls back to its last saved copy). Demo: http://localhost:3000 → "▶ RUN DEMO" (or http://localhost:3000/event/kyushu-2026?demo=1). Present in Chrome; Cursor's built-in browser injects attributes that trigger a harmless hydration warning.

Article `.txt` files are gitignored: they are used only for local quote verification. The UI shows at most a 15-word clause of each verified quote plus source, date and link.

## Live features

- **USGS live feed** (command screen): M4.5+ quakes from the past 7 days, polled every 60 s. Quakes within 200 km of a tracked plant list the downstream SYNTHETIC accounts. Proximity only: no tier is assigned without verified disruption reports. Offline, the last saved feed (`data/usgs_live_cache.json`) is shown as CACHED.
- **Paste article** (event workspace): paste any article; claims are extracted live, every quote is verified against the pasted text, and the blast radius recomputes in the browser. Pasted text is never written to disk. Pasted sources are tier 3; a claim becomes CONFIRMED only when a different publisher reports the same subject and claim type.
- **Activity feed**: logs verified/rejected claims and every tier change caused by a new source, a replay step or the persistence assumption.
- **Event brief** and **exposure by affected plant**: shown when no account is selected. The brief is citation-checked with the same validator as account summaries and pre-generated by `npm run explain`.
- **De-escalation example** (event 03, Taiwan 2024): "the bigger earthquake was the smaller problem". Replay T1→T5 to watch Northwind Electronics move REVIEW NOW → MONITOR → RESOLVED as verified recovery claims arrive. Not part of RUN DEMO.
- **Portfolio concentration** (command screen): supplier plants feeding the most SYNTHETIC accounts. Path counts only; no loss estimates.

## Pipeline

| Step | Command | Output |
| --- | --- | --- |
| USGS fetch (largest M6+ quake in window) | `npm run usgs` | `data/usgs_cache.json`, `data/events.json` |
| Claim extraction, zod validation, quote verification, status | `npm run extract` | `data/claims.json`, links `claim_ids` into `data/edges.json` |
| Citation-checked alert summaries and event briefs | `npm run explain` | `data/explanations.json`, `data/briefs.json` |

- Raw LLM output is cached per article in `data/extract_cache.json`, keyed by a hash of the article text: unchanged articles are never re-sent, so adding sources cannot shift earlier results. `npm run extract -- --fresh` forces re-extraction.
- Claims whose `evidence_quote` is not in the article (after whitespace/case normalization), or whose statement contains a dollar amount, percentage, duration or probability, are rejected and counted in the UI.
- Status: CONFIRMED if the source is tier 1–2 or 2+ independent publishers support the same plant + claim type; otherwise REPORTED. Replay recomputes statuses from only the sources in view.
- Company-level claims attach to every grouped plant of that company in the event region (`lib/groups.ts`) and are labelled "company-level report".
- De-escalation (`lib/blastRadius.ts`): plant status follows claims in publication order, DISRUPTED → RECOVERING → RECOVERED. Restart claims are classified from the verified quote; planned or expected restarts never change status. RECOVERING caps REVIEW NOW at MONITOR; a CONFIRMED full restoration marks the account RESOLVED.
- A magnitude in an article that differs from USGS is shown as CONFLICTING; the USGS value is always used.
- Real supplier edges are PUBLIC_VERIFIED only when a claim naming both sides exists; otherwise they show as INFERRED (dashed).
- Synthetic account edges get `first_seen_event = kumamoto-2016` when their upstream facility has a 2016 disruption claim.

## Code map

- `lib/blastRadius.ts`: affected facilities, BFS up to 3 hops, tiers, direct/indirect, memory badge, downstream accounts
- `lib/extract.ts`, `lib/link.ts`, `lib/explain.ts`, `lib/brief.ts`, `lib/usgs.ts`, `lib/usgsLive.ts`
- `app/page.tsx`: Command screen; `app/event/[id]/page.tsx`: Workspace
- `app/api/extract` (saved or pasted source), `app/api/explain`, `app/api/brief`, `app/api/live/usgs`: live calls with cached fallback
